:::article-block workspace
Проект отвечает на практический R&D-вопрос: как использовать несколько ИИ-агентов в разработке и не терять контекст, владение задачами, проверяемость и контроль.

:::article-block workspace-gallery
Среда объединяет долговременную проектную память, context engineering, RAG-style context retrieval, маршрутизацию моделей, tool use, оркестрацию задач и браузерные операции в один рабочий интерфейс для проверяемой разработки с ИИ.

:::article-block kanban-board
В центре находится исполняемая канбан-доска.

:::article-block column-settings
Каждая колонка запускает часть процесса и может получить свои действия, роли и пул специализированных агентов.

:::article-block open-source
Agent Portal построен на наборе MCP-серверов моего авторства, которые координируются open-source контуром управления (`mcp-agent-portal`). Этот контур оркестрирует исполнение агентов (Agent Pool), графовую кодовую аналитику (Project Graph), а также браузерную и терминальную автоматизацию, предоставляя чистый tool-use/function-calling контракт между агентами и продуктовой средой.

:::article-block process-path
Вместе настроенные колонки превращают доску в исполняемый процесс.

:::article-block human-decision
Конфликт возвращает карточку к решению человека. Процесс включает evals, guardrails и human-in-the-loop контроль при нештатных ситуациях.

:::article-block process-diagram
Для задач с кодом система создаёт изолированную рабочую копию и ветку. Один агент выполняет работу, другой независимо проверяет результат. Текущая R&D-линия проводит агентов по полному циклу разработки: взять задачу, доказать работоспособность, проверить и объединить.

:::article-block resource-groups
Модели и подписки объединяются в группы ресурсов, поэтому этап получает исполнителя с подходящими возможностями и доступным лимитом. Простую и разведочную работу выполняют быстрые модели, а сложные решения принимают сильные модели на основе сжатого проектного контекста.

:::article-block configuration-label
Вектор развития проекта направлен на отказ от монолитного приложения в пользу портативных конфигураций (Workspace-as-Config). В целевой архитектуре Agent Portal становится тонким хостом (предоставляющим чат, авторизацию и маршрутизацию моделей), а сам интерфейс и рабочие процессы динамически собираются агентами с помощью Symbiote Workspace.
