Текущая схема памяти использует один настроенный content root team-memory. Переиспользуемые skills находятся в `skills/`. Project-specific skills лежат в `workspace/<project>/skills/` рядом с контекстом проекта, который их активирует. Иерархии `/global/skills` или локальной `.workspace/skills` в реализации нет.

Resolver сначала определяет активные project contexts по пути репозитория и подсказкам релевантных файлов. Затем он перечисляет каталоги глобальных skills и skills этих workspace. Каждый элемент содержит tier и workspace, поэтому оркестратор применяет project-specific правила как более конкретные, а глобальные использует для незакрытых областей.

Такое разделение сохраняет факты проекта в его собственной области памяти. В делегированный prompt попадают только выбранный context package и skills, необходимые задаче. Shared clone остаётся единственным source of truth, а execution state и файлы репозитория сохраняют отдельные границы владения.
