Agent Pool планирует локальные агентные задачи через parser пяти полей cron и detached daemon. Schedule definitions и результаты хранятся в файлах, поэтому daemon продолжает работу после отключения IDE или MCP-клиента. Отложенные one-shot tasks используют ту же границу выполнения.

Daemon владеет PID lock file. При получении блокировки проверяется, жив ли записанный процесс; устаревшее владение можно заменить. Для каждой минуты scheduler также запоминает уже выполненный schedule и подавляет повторный запуск в том же временном слоте. Pipeline run signals используют атомарные файловые операции для связи MCP-сервера с daemon.

Реализация состоит из минимального cron parser, сохраняемого JSON-состояния, detached Node.js process и файлового владения. Она не зависит от SQLite-таблицы, блокировки через `ON CONFLICT` или отдельного Python scheduler. Гарантии нужно оценивать на фактически реализованной границе filesystem.
